## Three levels of copy and semantic review

**Local:** Replace claims such as “proven”, “verified” or “real” with the exact witness: source blob, test implementation, self-reported receipt, observed native execution or independent human review. A source OID does not prove the test executed or passed.

**Intermediate:** Each project case must connect *the user-level goal*, a historical failure, a specific code/test change, a negative oracle and remaining missing evidence. A local repair cannot certify an entire application or erase unknown indirect consumers.

**Global:** The shared pattern is evidence-bound, reversible engineering, **not a scientifically identified productivity effect of CORA**. Git comparisons between different deliverables, task sizes and author effort cannot establish a causal learning curve. LUMEN predates the creation of the CORA repository; NILO followed it. Both chronologies permit competing explanations. No independent A/B evaluation, real user comprehension study or independent scientific review is claimed.

## Exact-Git and human-authority boundary

For any commit: record repository, 40-digit commit SHA, changed file path, original Git file OID, engineering layer and claim limit. A source test or generated JSON may indicate an intended oracle; target-native execution, browser/device behavior, effective host governance and human release authority require separate evidence. Historical R4/R3 identities must remain frozen, not silently repinned to convenience HEADs.

CORA-METHOD guides third-party agents. CORA-ENGINE supplies local Git/source evaluations. Neither becomes a coding agent, a security signing service or an independent release approver.
