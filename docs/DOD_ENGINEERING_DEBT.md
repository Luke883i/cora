# Backward-derived DoD — debt discovery and CORA process orchestration

**Document status:** CURRENT
**Current scope:** Evidence-bound acceptance of debt and process analysis.
**Operational use:** Test retained debt signals on a pinned Git revision.
**Evidence:** Debt scanner and process suite with original-Git source replay.
**Limits:** Debt counts are not calibrated defects, financial liabilities or closure proof.


**G-scoped (demonstrable):** For a pinned commit and optional original bounded SARIF input, CORA creates a reproducible *read-only* multiscale debt-signal inventory with source IDs, type labels, uncertainty, human-review priorities, non-executable remediation instructions, and interoperable trend/process receipts. Individual processes and a coherent `full` read-only process can be enumerated and replayed. No finding authorizes deletion or unreviewed edits.

**G+ (NOT demonstrated):** universal technical-debt detection, calibrated precision/recall or confidence, certified ISO/SSDF compliance, scanner authenticity, verified runtime/cross-repo closure, economic savings, fully guarded automatic remediation or proof of no regressions on arbitrary software.

| Intermediate DoD | Local obligations | Mechanical gate |
| --- | --- | --- |
| I1 source identity | L1 fixed SHA / Git blob; L2 separate product/software/repo; L3 source vs third-party attestation | temp-Git fixture, self-report replay |
| I2 categories | L4 versioned finite taxonomy; L5 no source signal promoted to proved fault; L6 fixed remediation and human role | unit oracles and required fields |
| I3 multi-scale | L7 Python AST structural thresholds; L8 bounded history/change pressure; L9 architecture/product/role flags | fixture with shared and cross-product development |
| I4 external standards | L10 bounded SARIF 2.1; L11 path safety; L12 external provenance UNVERIFIED | malignant SARIF and forged report tests |
| I5 process catalog | L13 seven named safe independent processes; L14 `full` includes supported read-only methods; L15 never executes target code/LLM/deletion | CLI and adversarial fixture |
| I6 trend and governance | L16 new/persisting/not observed + unknown comparable; L17 priority is ordinal; L18 human-only remediation | Git two-commit fixture and policy tests |
| I7 reproducibility | L19 even re-signed corrupted receipts rejected by source replay; L20 two byte-identical seeded 1M synthetic runs; L21 CI Python 3.11/3.13 | CI artifacts + tests |
| I8 maintainability | L22 README first-screen identity; L23 CLI registry and docs in sync; L24 all pre-existing regressions | full test-suite and repository contract gate |

**Metric contracts:** `git_artifacts` = all tracked Git snapshot records; `python_ast_candidates` = `.py` paths, `python_ast_inspected` = readable parsable blobs within 512 KiB, `python_ast_coverage_fraction` = inspected/candidates (null when denominator zero); `findings` = source-specific rules raised; `unresolved_obligations` = distinct debt collection gaps. All metrics are scoped; no monetary debt or economic interest is inferred. A zero finding count with missing coverage is **not** zero debt.

**Acceptance checklist:** exact Git replay; review category and source; visible missing evidence; independent oracles; no shell or target-code execution in debt/full; workflow fails on mismatch; reviewer checks CI; no merge on failed or incomplete gates. Manual pilot on unrelated maintained repositories and independent scanner provenance remain open.
