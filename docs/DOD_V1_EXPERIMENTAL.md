# CORA v1.experimental — global, intermediate and local DoD

**Candidate package:** `1.0.0a1` (pre-release; no stable v1 API or distribution promised). A terminal global PASS is prohibited when an independent human or external hosting proof remains absent. Each gate has a responsible human and a reproducible witness; a large synthetic run never substitutes for source evidence.

## Global gate G-v1 (AND-composition)

An engineer new to CORA can, from the repository root alone, identify the **product**, **software components**, **repository boundary**, **supported and unsupported transformations**, **single-file investigation workflow**, **human decision pathway**, **evidence provenance**, and **distribution status**; inspect a Git-committed artifact role and its complete declared role set; reproduce read-only self-audit and tests; and understand why an unreferenced file is not certified deletable.

`G-v1 := I1 AND I2 AND I3 AND I4 AND I5 AND I6`; no averaging or credit from an unrelated synthetic PASS. Status is **BLOCKED** until an independent novice first-read test, hosting enforcement evidence and real external pilot observations are attached.

### Human novice-engineer acceptance sheet (not automated)

Provide **only** the repository root, with no prior conversation. Observe a genuinely unfamiliar engineer locate in five minutes: (1) product purpose and limits, (2) software entrypoint and release tools, (3) Git/CI governance, (4) audit and per-file lab commands, (5) roles of one multi-purpose test/contract file, (6) security and approval pathway, (7) unsafe task that CORA refuses. Record completion time, mistaken assumptions and a reviewer signature or organizational equivalent. **PASS** requires all seven without claiming safe automatic deletion. This test has not been conducted by the CI or by the assistant.

### Repository management and standards

We use [OpenSSF OSPS baseline](https://baseline.openssf.org/), [GitHub protected branch guidance](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches), [SemVer](https://semver.org/) and Python packaging practice as adversarial design references, **not** as compliance certifications. The private repository's available hosting controls must be checked separately; a CODEOWNERS file is not evidence that required reviews are enforced. Pre-release build reproducibility is not signed provenance.

### Closure report

Automated PASS_SCOPED: committed multi-role declarations, finite-model saturation without new categories after M, report revalidation, tests, packaging. Human/external BLOCKED: independent first-read, external production repository trials, hosted review/CI control proof, calibration and authentic runtime coverage. The final status cannot be upgraded until those witnesses exist.
